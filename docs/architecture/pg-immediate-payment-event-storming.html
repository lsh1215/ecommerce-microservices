Command Event Policy Aggregate Read Model
주문 생성과 재고 예약
주문 생성 요청 User → Traefik → Order. JWT에서 식별된 customerId와 주문 항목을 전달한다.
→
Order / SagaInstance PENDING Order와 STOCK_RESERVATION_PENDING SagaInstance를 먼저 저장한다.
→
재고 예약 요청 Order transaction 밖에서 Product에 variant별 reserve를 호출한다.
OrderCreated 재고 예약 성공 후 OrderItem을 저장하고 Kafka outbox에 결제 요청 이벤트를 남긴다.
결제 요청 생성
OrderCreated 수신 정책 중복 eventId는 processed_event로 차단한다.
→
Payment orderId unique key로 주문당 결제 1건만 생성한다. 상태는 PENDING.
→
PaymentAttempt REQUESTED 상태, requestedAt, idempotencyKey, retryCount를 저장한다.
PaymentAttemptHistory REQUESTED 이력을 append한다. 장애 분석과 재처리 판단의 기준이 된다.
PG 승인 처리
PaymentAttemptProcessor REQUESTED/RETRYABLE_FAILED attempt를 짧은 트랜잭션으로 claim한다.
→
PROCESSING_STARTED 처리 시작 시각과 retryCount를 먼저 기록한다.
→
PG 승인 API DB 트랜잭션 밖에서 호출한다. 현재는 stub adapter가 승인/거절을 시뮬레이션한다.
retry 가능 오류 네트워크/일시 장애는 RETRYABLE_FAILED로 남기고 다음 processor 주기에 재시도한다.
결제 결과와 보상
PaymentCompleted Payment와 Attempt를 COMPLETED로 전이하고 transactionId를 기록한다.
→
Order Paid Order는 CONFIRMED, PAID로 전이하고 SagaInstance는 COMPLETED가 된다.
↘
PaymentFailed 재시도 불가능 실패는 FAILED 이력과 함께 실패 이벤트를 발행한다.
Compensation Order를 CANCELLED로 전이하고 Product 재고 해제를 트랜잭션 밖에서 호출한다.

트랜잭션 원칙

  • Order DB transaction 안에서 Product/Payment/PG를 호출하지 않는다.
  • Payment DB transaction 안에서 PG를 호출하지 않는다.
  • 외부 호출 전후 상태를 DB 이력으로 남긴다.

운영 관측 포인트

  • REQUESTED → PROCESSING_STARTED 지연
  • PROCESSING_STARTED → COMPLETED/FAILED 지연
  • RETRYABLE_FAILED 누적과 retryCount 분포

증거 수집 포인트

  • 결제 성공률과 실패 이벤트 수
  • PaymentAttemptHistory 행 수와 상태별 분포
  • Order SAGA COMPLETED/COMPENSATED 상태 전이
